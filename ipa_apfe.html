テクノロジー：信頼性/可用性

大分類 02: コンピュータシステム
中分類 04: システム構成要素

応用情報処理過去問

  • 4.2評価指標

稼働率

  • MTTRは、平均修復時間（Mean Time To Repair）
    • システムや機器が故障してから完全に復旧するまでの平均時間を指します
  • MTBF (平均故障間隔):
    • 故障と故障の間の平均時間。MTTRと合わせて、システムの信頼性を評価するために用いられます.﻿
  • MTTF (平均故障寿命):
    • 製品が故障するまでの平均時間。MTTRとは異なり、修理不能な故障を対象とします.﻿
  • RTO (目標復旧時間):
    • 災害発生時など、システム停止からの復旧目標時間。MTTRは、一定期間の平均値であるのに対し、RTOは単一のイベントに対する目標値です.﻿
  • RPO 目標復旧時点（Recovery Point Objective）
    • RPOは、障害発生時に、過去のどの時点のデータまで復旧させるかの目標値を指します。
  • RLO 目標復旧レベル (Recovery Level Objective)
    • システム障害発生時に、「どのレベル（水準）で」システムや業務を復旧させるかという目標値です

RASIS

  • RASIS
    • Reliability (信頼性)
      • システムが故障しにくい性質のこと。﻿
      • 信頼性は、システムが安定稼働し続ける平均時間である平均故障間隔(MTBF)を指標として判断します。
    • Availability (可用性)
      • システムがどれだけ利用可能な状態を維持できるかを示す指標。﻿
      • システムの可用性を判断する指標となるのが「稼働率」です。
    • Serviceability (保守性)
      • システムのメンテナンスや修理のしやすさ。﻿
      • 平均修復時間（MTTR）﻿が指標となる
    • Integrity (保全性)
      • データが正確で、一貫性を保っている状態。﻿
    • Security (安全性/機密性)
      • システムが不正アクセスや情報漏洩から保護されている状態。﻿

モジュール強度

  • モジュール強度
    1. 暗合的強度（Coincidental Strength)
      全く関連のない機能が、偶然同じモジュールにまとめられている状態
    2. 論理的強度（Logical Strength） A, B, Cといった複数の類似する機能が、論理的にまとめて一つのモジュールに収められている状態﻿
    3. 時間的強度（Temporal Strength） 特定の時点で一度に実行される一連の初期設定処理などが、まとめて一つのモジュールに収められている状態
    4. 手順的強度（Procedural Strength） 実行される順番が決まっている一連の処理などが、まとめて一つのモジュールに収められている状態
    5. 逐次強度（Communicational Strength） あるモジュールでの処理結果を次のモジュールで利用するなど、データや処理結果が連続して使われる関係にある機能がまとめられている状態
    6. 情報的強度（Sequential Strength） 処理の対象データと、そのデータを処理する機能が、一つのモジュールにまとめられている状態﻿
    7. 機能的強度（Functional Strength） 単一の機能を実行するために、関連するデータと処理が全て一つのモジュールに収められている状態で、これは最もモジュール強度の高い設計です﻿

モジュール結合度

ソフトウェア設計では、一般的に以下の6つのレベルでモジュール間の結びつきが定義されている。

  • モジュール結合度
    1. データ結合（Data Coupling）:モジュール間で必要なパラメータのみを渡す最も独立性の高い結合です。
    2. スタンプ結合（Stamp Coupling）:複合データ構造全体を渡す場合。
    3. 制御結合（Control Coupling）:モジュール間で制御情報を渡す場合。
    4. 外部結合（External Coupling）:共通の外部データ領域（グローバル変数など）を共有する場合。
    5. 共有結合（Common Coupling）:複数のモジュールが同一のグローバルなデータ領域にアクセスする場合。
    6. 内容結合（Content Coupling）:あるモジュールが他のモジュールの内部構造やロジックを直接変更する場合、最も結合度が高い状態です。

ITサービスマネジメントのプロセス

ITサービスマネジメントのベストプラクティスをまとめたITIL v3（IT Infrastructure Library version 3）における、 サービスサポートとサービスデリバリの2つの主要な領域にプロセスが含まれます。
ITIL v3では、ITサービスマネジメントを2つの主要な領域に分けて、それぞれに複数のプロセスを定義しています。

  1. サービスサポート (Service Support):
    1. インシデント管理 (Incident Management):サービスの中断を迅速に解決し、通常の状態に戻すことを目的とします。
    2. 問題管理 (Problem Management):インシデントの原因を特定し、再発防止策を講じることを目的とします。
    3. 構成管理 (Configuration Management):ITサービスの構成要素を管理し、変更を追跡することを目的とします。
    4. 変更管理 (Change Management):ITサービスの変更を計画、承認、実施、管理することを目的とします。
    5. リリース管理 (Release Management):新しいサービスや変更をリリースし、展開することを目的とします。サービスデスク (Service Desk):
    6. ユーザーからの問い合わせや要求に対応する窓口となります。﻿
  2. サービスデリバリ (Service Delivery):
    1. サービスレベル管理 (Service Level Management):サービスレベル目標を設定し、達成状況を監視することを目的とします。
    2. ITサービス財務管理 (IT Service Financial Management):ITサービスのコストを管理し、予算を立てることを目的とします。
    3. 可用性管理 (Availability Management):ITサービスが利用可能な状態を維持することを目的とします。
    4. ITサービス継続性管理 (IT Service Continuity Management):災害時など、サービスが中断した場合の復旧計画を立てることを目的とします。
    5. キャパシティ管理 (Capacity Management):ITサービスの需要と供給のバランスを管理することを目的とします。

ECRS（イクルス）

業務改善を進める際の、基本的な改善発想視点として使用する。
以下がECRSの四つの要素。

  1. Eliminate（エリミネート）
    • 日本語では「排除」
    • 該当する業務やその内の一部作業をなくせないか考えることを指す。業務をやめることはコストをかけずにでき、改善効果が大きい。
  2. Combine（コンバイン）
    • 日本語では「統合・分離」
    • 「統合」は二つ以上の業務を同時にできないか考えることを指し、「分離」は1人で行っている業務を2人以上で分担・同時並行し、スピードアップできるか考えることを指す。
  3. Rearrange（リアレンジ）
    • 日本語では「交換」
    • 作業の順序や作業タイミングを変えることで業務を改善できないか考えることを指す。
  4. Simplify（シンプリファイ）
    • 日本語では「簡素化」
    • 業務をより楽で簡単にできる方法がないか考えることを指す。システム化・自動化もこれに含まれる。

SL（Situational Leadership）理論

状況に応じてリーダーシップスタイルを変えるリーダーシップ理論 部下の「能力」と「意欲」のレベルに応じて成熟度を4段階に分けて、リーダーの関わり方（リーダーシップスタイル）を変化させます。﻿

  1. 「教示型」：指示型リーダーシップ (Directing/S1)
    • 部下の状態:能力も意欲も低い。﻿
    • リーダーの行動:具体的な指示を出し、行動を細かく管理する。﻿
  2. 「説得型」：コーチ型リーダーシップ (Coaching/S2)
    • 部下の状態:能力は低いが、意欲はある程度ある。﻿
    • リーダーの行動:指示と行動の支援の両方を増やし、多くの説明をしながらサポートする。﻿
  3. 「参加型」：援助型リーダーシップ (Supporting/S3)
    • 部下の状態:能力はあるが、意欲や自信が不安定。﻿
    • リーダーの行動:サポートや共感の度合いを高くし、部下の意思決定を促しながら行動の指示は減らす。﻿
  4. 「委任型」：委任型リーダーシップ (Delegating/S4)
    • 部下の状態:能力も意欲も高い。﻿
    • リーダーの行動:権限を委任し、部下の自己決定に任せる

産業財産権

産業財産権とは、特許権、実用新案権、意匠権、商標権の4つの権利をまとめて指す言葉です

  • 特許権
    • 新規で高度な発明を保護する権利です。例えば、新しい機械の仕組みや新しい化学物質などが該当します。﻿
  • 実用新案権:
    • 物品の形状、構造、組み合わせに関する考案を保護する権利です。例えば、便利な道具や器具の改良などが該当します。﻿
  • 意匠権
    • 製品のデザインを保護する権利です。例えば、新しい形状のスマートフォンや、特徴的なデザインの自動車などが該当します。﻿
  • 商標権
    • 商品やサービスにつける名称やロゴマークを保護する権利です。例えば、企業のロゴや、商品名などが該当します。﻿
